---
title: Build a component & variants
description: An MCP walkthrough for going from reference to a reusable component with variants — reference frame, master, component set, instances, and PATH overrides.
---

import { Step, Steps } from 'fumadocs-ui/components/steps';

This guide builds a reusable button component with variants, grounded in a
reference. Components in Fantaisa are **reference-first**: gather or generate the
visual direction, build the editable master, then derive variants and instances.

<Steps>

<Step>

### Search, then capture a reference

When asked to create a component, search existing components first so you don't
duplicate one. If the visual direction is open, gather or generate references and
capture them as a reference frame with source and influence so the user can favor
or downweight inspirations.

```json title="create a reference frame"
{"name":"create_reference_frame","arguments":{
  "name":"Button refs","source":"dribbble","comment":"primary CTA, pill, medium weight","influence":0.6
}}
```

</Step>

<Step>

### Build the master with auto-layout

Build the button as a real auto-layout stack (see
[Build a card](/docs/guides/auto-layout-card)) — a frame containing a label,
laid out with padding and gap. Size the label box for the longest text it will
hold; there is no resize tool.

```json title="batch_design: assemble the master"
{"name":"batch_design","arguments":{"ops":[
  {"tool":"create_frame","args":{"name":"Button","fill":"#3B82F6"}},
  {"tool":"create_text","args":{"name":"Label","text":"Continue","size":15,"weight":600,"color":"#FFFFFF"}},
  {"tool":"reorder","args":{"node":"Label","into":"Button","to":"front"}},
  {"tool":"set_auto_layout","args":{"node":"Button","direction":"horizontal","gap":8,"padding":12,"primary_sizing":"hug","counter_sizing":"hug"}}
]}}
```

</Step>

<Step>

### Promote to a component, then define a variant set

Turn the frame into a component master, then group masters into a variant set so
consumers can switch between states.

```json title="define the component and a variant set"
{"name":"batch_design","arguments":{"ops":[
  {"tool":"define_component","args":{"node":"Button","name":"Button"}},
  {"tool":"define_component_set","args":{"name":"Button","members":["Button/Primary","Button/Secondary"],"property":"variant"}}
]}}
```

</Step>

<Step>

### Insert instances

Drop instances of the component. Like `create_*`, `insert_instance` places on the
active page — reparent it into its container with `reorder` if it belongs in a
frame.

```json title="insert an instance"
{"name":"insert_instance","arguments":{"component":"Button","x":0,"y":0}}
```

</Step>

<Step>

### Override — use a PATH for nested targets

`set_instance_override` resolves the component root or a **direct** child by node
id. A descendant inside a sub-frame needs the full `target` **PATH** array
`[subgroup, …, leaf]`, or the override silently no-ops.

```json title="override a direct child"
{"name":"set_instance_override","arguments":{"instance":"btn_1","target":"Label","text":"Get started"}}
```

```json title="override a nested descendant with a PATH"
{"name":"set_instance_override","arguments":{"instance":"btn_1","target":["Content","Label"],"text":"Get started"}}
```

<Callout type="warn">
  If you recreate a master child, **re-point overrides at the new id** — an
  override aimed at a stale id silently does nothing.
</Callout>

</Step>

<Step>

### Verify against the reference

Screenshot the variant set as a single frame and compare it against the saved
reference, then critique before saving.

```json title="export, compare, review"
{"name":"export_png","arguments":{"node":"Button"}}
```

```json
{"name":"compare_screenshot","arguments":{"node":"Button","reference":"Button refs"}}
```

```json
{"name":"review_design","arguments":{"node":"Button"}}
```

Iterate against the reference after each major change so the look-and-feel does
not drift.

</Step>

</Steps>

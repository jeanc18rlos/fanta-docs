---
title: Review and revision
description: Inspect an agent's design changes and iterate with screenshots, source files, and undo.
---

Review an agent edit in the editor before treating the design as finished. Fanta provides canvas screenshots, layer inspection, an undoable edit history, and project source files for this loop.

## Review a canvas edit

Ask the agent to capture a screenshot after applying an edit. Check the target frame at its intended size: alignment, text overflow, clipping, spacing, contrast, image crop, and visual hierarchy. Use <code>batch_get</code> to inspect precise properties when a screenshot is ambiguous. Give the next revision as a short list of observable changes.

A <code>batch_design</code> edit is an ordered, atomic undo transaction. If an operation fails, the entire batch rolls back and the result identifies the failing operation. If a completed batch is wrong, undo it in Fanta or request a corrective batch. Work with exact node IDs obtained from the current document.

## Review source changes

Pages and component masters can be stored as FNX files inside a project. Read them through <code>read_fnx_source</code> or your normal file tools. The MCP reader slices by 1-based line offset, so follow its <code>next_offset</code> before replacing a file. Check a complete candidate with <code>validate_fnx_source</code> before writing. External edits to an open project's FNX files are picked up by the editor after a short delay. A source parse error leaves the last valid canvas state visible while you fix the file. See [FNX source](/docs/formats/fnx).

Source files are useful for Git review. Check the actual canvas too: a clean textual diff alone does not establish that the rendered design is correct.

## Comments and handoff

Fanta's canvas comments can attach pins to design positions and hold replies, mentions, attachments, and resolved state. They are stored as project page metadata. External agents can call <code>list_comments</code> for unresolved threads on the active page, or include resolved threads and choose a page. Use <code>reply_comment</code> with the exact thread ID to answer, and set <code>resolve: true</code> only after the request has been verified. The in-app agent's related tool is <code>design_comments</code>. Comments do not appear in PNG, JPG, SVG, or PDF exports.

When the design is ready, export the selected layers or active page from the editor. For another editable copy, keep the native project directory or use a supported snapshot workflow. See [formats and interoperability](/docs/formats).

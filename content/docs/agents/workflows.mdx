This page covers how agents actually get work done on the canvas — first solo,
then as a fanned-out team — and the discipline that keeps many agents from
stepping on each other in one shared document.

## The single-agent loop

Every agent runs the same loop. The point is to **inspect before building** and
**verify before saving** — never build blind, never save unverified.

<Steps>
<Step>

**Orient.** Call `agent_playbook` then `get_guidelines` to load the rules of
the road, the style packs, and the token/component conventions for this doc.

</Step>
<Step>

**Inspect.** Read the live state with `get_editor_state`, `get_document`, or
`snapshot_layout` so the model knows what already exists before it adds to it.

</Step>
<Step>

**Build.** Create nodes with `create_*` or a batched `batch_design`, then
assemble bottom-up: leaves into rows, rows into sections, sections into the
page. Reparent with `reorder` and structure with `set_auto_layout`.

</Step>
<Step>

**Verify.** Export a frame with `export_png` / `get_screenshot`, optionally
`compare_screenshot` against a reference, and run `review_design` for a
deterministic audit.

</Step>
<Step>

**Save.** Persist with `save_document`. In-memory state is not auto-persisted.

</Step>
</Steps>

```text title="Solo agent — example tool sequence"
agent_playbook
get_guidelines
get_editor_state
create_frame { name: "Pricing card", width: 320, height: 420 }
reorder      { node: <card>, into: <section>, to: "front" }
set_auto_layout { node: <card>, direction: "vertical", gap: 16, padding: 24 }
export_png   { node: <card> }
review_design
save_document
```

<Callout type="warn">
Always pass a frame `node` to `export_png` / `get_screenshot`, and keep frames
≤ 1920×1080. With no `node` these default to the whole document (every page
across world space) and time out. Never screenshot a page or the bare canvas.
</Callout>

## The multi-agent model

A `MultiAgentOrchestrator` fans out **N concurrent agents (1–6)**. Each agent
clones the document and works in isolation, capturing its own `applied_ops`.
When the team finishes, `run_merged` replays every agent's ops onto the real
document **inside one history transaction** — so the entire team's work is a
**single undo step**.

Conflict handling is simple and predictable:

- **New nodes never conflict.** IDs are globally unique, so every agent's
  freshly-created nodes coexist.
- **Base-node edits are last-writer-wins** (v0). If two agents edit the same
  pre-existing node, the last write applied during the merge wins.

### Launch a visible team

Over the MCP, `start_agent_team` spins up a team you can *watch*: it draws
on-canvas cursors, focus frames, and step markers as the agents work.

```json title="start_agent_team"
{
  "prompt": "Build a 3-screen onboarding flow: welcome, permissions, done",
  "provider": "claude",
  "agent_count": 3,
  "visible": true
}
```

`provider` is one of `"claude"`, `"codex"`, or `"glm"`; `agent_count` is `1..6`.
Set `visible: true` for the live cursor/focus/step overlay.

## Discipline for one shared document

When multiple agents work the **same** running document, the editor serializes
frames so writes are safe — *but only if every batch follows this discipline*.
Bake these into each agent's instructions:

- **Disjoint world regions.** Give each agent its own region of world space so
  their work never overlaps geometrically. Pack each region compactly; do not
  scatter frames across thousands of pixels.
- **Unique names.** Namespace node names per agent so nothing collides or gets
  re-resolved by name.
- **Capture ids at creation.** Reads are active-page-scoped. Don't rely on
  re-finding a node across pages later — record each id the moment you create
  it and reuse the captured id.
- **Prefix `set_active_page`.** Start every batch by setting the active page so
  cross-page reads and writes target the page you intend.

<Callout type="info">
These rules apply equally to a launched team and to several independent agents
you point at the same `:3846` editor. New nodes are conflict-free; the
discipline is about keeping reads correct and regions clean.
</Callout>

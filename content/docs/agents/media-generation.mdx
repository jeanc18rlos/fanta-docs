Agents can generate media directly from the canvas. Generation is **always
asynchronous** — it never blocks the editor — and results **enter the document**
(images) or **open the matching workbench tab** (video, audio, 3D).

## Images

`generate_image` starts an async image job and returns a job handle; the result
enters the doc when it settles. Poll the job with `get_image_job`.

```json title="generate_image"
{
  "prompt": "isometric pricing illustration, soft teal palette, no text",
  "model": "<replicate-model-id>",
  "count": 1
}
```

```json title="get_image_job"
{ "job": "<job-id>" }
```

<Callout type="info">
Image jobs run off the UI thread, so the canvas stays interactive while a job
is in flight. The finished image is placed into the document for you — no
manual import step.
</Callout>

## Video, audio, and 3D

`generate_media` covers the heavier modalities. Pass the `modality`, a `prompt`,
and a Replicate `model` id. The result **auto-saves and opens the matching
workbench tab** (video, audio, or 3D), ready to edit.

<Tabs items={['Video', 'Audio', '3D']}>
<Tab value="Video">

```json title="generate_media — video"
{
  "modality": "video",
  "prompt": "slow dolly across a neon-lit product shelf, 4s loop",
  "model": "<replicate-model-id>"
}
```

Opens the video workbench tab with the generated clip.

## Waiting for results

You have two ways to wait, depending on whether the agent wants to keep working
or block on the result:

- **Poll** with `get_image_job` (image jobs) or `get_async_state` (any async
  job) — non-blocking; check status and pick up the result when ready.
- **Block** with `wait_settled` — suspend until the job finishes, then continue.

```text title="Generate, then continue when ready"
generate_image  { prompt: "...", model: "...", count: 1 }   # → job-id
# Option A — keep working, poll occasionally:
get_async_state { job: <job-id> }
# Option B — block until done:
wait_settled    { job: <job-id> }
# image is now in the doc → place / arrange / review_design
```

<Callout type="warn">
Prefer the offline mock when validating generation wiring, and make at most one
cheap real provider call (e.g. `count: 1`) only when the provider integration
itself changed. Generation calls cost money.
</Callout>

## Generate, then ground

Generated media pairs naturally with
[reference-grounded design](/docs/agents/reference-grounded): generate
candidate images, board them with `create_reference_frame`, then build against
them and compare each iteration.

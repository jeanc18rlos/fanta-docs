---
title: Architecture
description: How Fanta’s app shell, design engine, source files, and MCP connect.
---

Fanta’s desktop executable is built by the `zed` Cargo package and named `fanta`. Its shell is a fork of Zed. `fig_viewer` connects the design UI, canvas, project persistence, and local MCP server to the vendored design engine.

| Area | Source |
| --- | --- |
| App shell and executable | `crates/zed` |
| Design UI, source reload, export, MCP | `crates/fig_viewer` |
| Agent operation types and guidelines | `crates/design_surface` |
| Scene graph and edit operations | `crates/fanta-doc` |
| `.fnx` parser and printer | `crates/fanta-fnx` |
| Project layout and `.fant` format | `crates/fanta-format` |
| Figma import | `crates/fanta-fig-interop` |
| Canvas, rendering, text, human tools | `fanta-canvas`, `fanta-render`, `fanta-text`, `fanta-tools` |
| Presentation engine | `crates/fanta-present` |

A project contains `fanta.json`, `.fnx` source under `pages/` and `components/`, assets, and an `AGENTS.md` seed. Canvas operations autosave to source; source changes reload the canvas; Git tracks the folder.

The external MCP server runs in the app over a private Unix socket. `fanta --mcp-stdio` discovers the socket and bridges a client to the focused design. Six tools use the shared `design_surface` provider; `batch_design` applies typed `DesignOp` values in one undoable transaction. The older `fanta-app` / `fanta-ai` crate map and fixed HTTP port do not describe this checkout.

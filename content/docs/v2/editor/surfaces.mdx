# Editor surfaces

## Canvas and Layers

The canvas shows the active page and its selectable layers. The Layers panel lets you select and range-select layers, expand groups, rename nodes, toggle visibility and locking, and drag layers above, below, or inside other nodes. When you open a component master, its root appears as an editable row in Layers; expand it to see the master's children. Its context menu includes duplicate and delete, copy as SVG or PNG, copy properties, move to page, group and ungroup, frame or section conversion, flatten, outline stroke, mask, media replacement and cropping, layout, and component actions. The available actions depend on the layer.

The Pages area of Layers creates, selects, renames, duplicates, reorders, and deletes pages. It also includes a page link action and name/text search and replace. Right-click on the canvas for a shorter menu tailored to what you clicked, including direct text, vector, image, media, and component actions. [Canvas tools →](/docs/v2/editor/tools)

Drag the edge of the Layers or Properties sidebar to resize it. The panel contents respond as the width changes.

## Files and Project Assets

The file inspector shows project files and an **Assets** section for stored images, SVG, video, and audio. Generated results can be added to this library without creating a page layer. Choose a target page under **Place in** and use the asset row's **+** button when you want a layer. Missing files or unsupported formats show a disabled placement action with a reason. [Project Assets →](/docs/v2/editor/assets)

## Variables

The Variables workspace manages collections, modes, values, aliases, and bindings. Create a collection and variable, set mode values, then bind compatible selected layer properties. Scope a mode to preview a different value set.

## Fill a template

The lock button above the Design inspector switches this window between editing a template and **Fill In Template** mode. In Fill mode, supported canvas gestures, Delete, Duplicate, text editing, and Design inspector edits check the selected layer's template rules and show a notice when a change is refused. The button returns you to template editing; it does not change the saved rules.

Template rules can currently be authored in FNX or through the Rust design API. The inspector cannot show or edit the rules, and placeholder overlays are not displayed. Fill mode does not yet check multi-selection arrange and transform commands, variable bindings, or grouping, so check the result before sharing a filled design. [Template rules and data filling →](/docs/v2/concepts/templates)

Fill mode is implemented in Fanta 2.0 source. The signed 1.0 Public Alpha screenshot below and the current public installer do not establish this workflow.

## Code

The Code workspace opens the active page's `page.fnx` and `page.json`, or a component master's `master.fnx` and `def.json`. It also lists the project-wide `doc/variables.json`, `fanta.json`, and, for older projects that have one, `workspace.fnx`. Select **FNX**, **JSON**, or **variables.json** to edit that source file. The manifest and legacy workspace source are read-only in this pane. Opening Code from Variables selects `variables.json`. **Find** searches the selected source buffer. Save the design once before opening source. Save or discard canvas changes before editing source; while an editable source buffer has unsaved changes, canvas content editing is locked, but pan and selection remain available.

While a source draft is unsaved, select one canvas layer to read its last accepted properties in the Design inspector, including position, size, and layout gap. These rows cannot be edited until the draft is saved or discarded. With no selection or a mixed selection, the inspector asks you to select one layer. A source draft also blocks **Go to main component** when that action would switch page or component scope; save or discard the draft first.

Save source to validate the edited file against the project, write it, and reload the canvas. FNX saves also maintain its ID sidecar. Invalid JSON stays in the editor with an error and does not replace the saved file or the last good canvas. If multiple editable source files have changes, Fanta saves and validates them in sequence. **Discard draft** discards unsaved edits in the selected source file only; check the other editable files for drafts. Resolve any on-disk file conflict before retrying. When an in-app agent is writing the selected FNX file, Code shows its name and can follow its live source location. Choose **Pause follow** to navigate independently, and **Follow** to resume.

The canvas can also show an **Agents** control for active design agents. Select an agent to follow its current page or component and its Canvas, Variables, or Code workspace. Select the agent again to stop following. Source activity can open the relevant source tab. A clean canvas tab restores its project, page, or component location when the workspace reopens.

Fanta saves an intentionally empty design tab layout, so restarting does not reopen a tab that you closed. Explicitly opening that project again opens one tab; repeating Open reuses it after a project manifest replacement. These paths have bounded source tests; installed-app behavior beyond the recorded workflows remains unverified.

## Dev mode

Dev mode is a read-only artwork inspection session with page-bound measurements and annotations. It starts on a loaded canvas, activates Inspect, and offers **Inspect**, **Hand**, **Measurement**, **Annotation**, and **Saved Code**. The Code workspace is read-only while Dev mode is active; Variables is unavailable. A **Readiness unavailable** control is disabled in the current build. See [Dev mode](/docs/v2/editor/dev-mode) for the workflow.

## Motion

Motion mode shows the animation timeline and Motion inspector. Create or select a clip, add an animation to one selected layer, and preview or edit keyframes at the playhead. See [Motion](/docs/v2/editor/motion) for properties, timing, and current limits.

## Plan & Build

Open **Plan & Build** from the Agent Panel's new-thread menu or the Design menu. It starts an empty Plan-profile thread for the open design. Write a brief; the agent can read the design and propose a plan. After a successful plan response, **Apply plan** switches the thread to Write so the agent can build on the canvas. Each canvas batch the agent applies is its own undo step. This source workflow has a bounded test for opening the Plan thread; a complete build has not been verified against a model from the app. [Agent workflows →](/docs/v2/agents)

## Prototype and comments

Use the Prototype inspector controls to connect triggers and actions, then **Present** to test the flow. The Comments mode and tool provide a page-anchored discussion surface with threads, replies, attachments, mentions, resolution, and time-linked comments on motion clips. The document Comments panel lists comments across pages and opens the selected thread. See [Comments](/docs/v2/editor/comments) for mentions, attachments, replies, and reviewed Agent drafts.

Fanta has a live local design tool interface for agents. Its operations cover creating common nodes, changing style and layout properties, and inspecting structure; it does not use a required fixed HTTP port. See [agent integration](/docs/v2/plugin) and [Settings](/docs/v2/editor/settings) for current setup and build differences.

Layer behavior is in `crates/fig_viewer/src/design_panel.rs` and `crates/fig_viewer/src/layer_context_ops.rs`. Variables and Code are in `crates/fig_viewer/src/variables_workspace.rs` and `crates/fig_viewer/src/code_workspace.rs`.

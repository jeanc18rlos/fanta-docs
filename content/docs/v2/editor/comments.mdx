# Comments

Comments are anchored to a point on a design page. They are saved in page metadata, so they travel with the project. Open **Comments** mode or choose the **Comment** tool (**C**), click the canvas to place a pin, write a message, and send it. A draft does not become a saved comment until you send it.

Click a pin to open its thread. The thread shows the original message, replies, author, and relative time. You can reply, resolve or reopen the thread, delete it, and copy its text. The document **Comments** panel lists threads from all pages by their opening message. Select a row to open every message and a reply composer on a page of the panel; use **All Threads** to return to the list. The panel shows open and resolved counts and can hide or show resolved threads. A pin click still opens the thread on the canvas. Dev mode can read and copy comments, but its thread mutation controls are disabled.

In a new comment or reply, **Enter** sends the message, **Shift+Enter** adds a line, and **Escape** cancels a new draft. If a reply is unsent, Fanta asks you to send or clear it before returning to the thread list. The same draft protection applies when switching threads or placing another pin.

## Add context to a message

The composer has controls to mention an agent or layer, attach images or files, and choose an AI skill. Skills are **Summarize**, **Search**, **Format**, and **Review**. When a message with a skill is posted, Fanta opens its prompt as a reviewed draft in the Agent Panel; posting the comment does not submit the agent run. Attachments are saved as path references in comment metadata rather than embedded bytes, so keep referenced files accessible to collaborators.

You can attach context to the initial message or a reply. If a reply has unsent text or attachments, Fanta asks you to send or clear it before switching to another thread or placing another comment. If posting fails, the composer retains its contents for retry.

## Layer-anchored review findings

Fanta can attach a comment to a layer and a point within it. The pin follows that layer when it moves; if the layer is removed, the saved page position remains. A review finding can include an **Info**, **Minor**, **Major**, or **Blocker** severity; a category such as layout, accessibility, or motion; and an ID linking findings from the same review run. These fields are stored with the thread, so reviewers can revisit the finding in context.

An agent may also attach a suggested fix made of design-edit operations. The thread shows its summary and an **Apply suggested fix** button. Applying it is a separate user action and one undoable design change. A review finding by itself does not edit the design. [AI Review](/docs/v2/agents/in-app-ai) prepares a draft for the agent; review work begins when you send it.

The local MCP bridge exposes `add_comment` for new anchored findings, while `list_comments` returns the pin's current resolved position and `reply_comment` continues an existing thread. See [comments and review threads](/docs/v2/tools/comments).

## Comment on motion

In **Motion**, use the time comment control at the current playhead, then place a pin and send the comment. Its anchor stores both clip and time. The document Comments panel labels a timed thread and navigates to that clip and time when opened. See [Motion](/docs/v2/editor/motion).

Implementation: `crates/fig_viewer/src/comments.rs` defines page metadata, threads, replies, attachments, skills, and motion anchors; `crates/fig_viewer/src/comments_ui.rs` handles composer and canvas interactions; `crates/fig_viewer/src/comments_panel.rs` lists document comments.

## Status of Fanta 2.0

Fanta 2.0 is in development and has no installer yet. This map describes its source; its features have source and test coverage, but no installed-app acceptance. The app you can install today is the Fanta 1.0 Public Alpha, documented in the [1.0 capability map](/docs/capabilities). To try 2.0, [build it from source](/docs/v2/getting-started/install).

Fanta is a design editor whose working document is a project folder. You can create a design on the canvas, inspect and edit its `.fnx` and managed JSON source, ask an agent to work on the open design, and review the saved files in Git. This map follows [fanta-edit main at `d4fe647`](https://github.com/jeanc18rlos/fanta-edit/tree/d4fe64713e8615607878d896049f88379e7cc39f) as of October 29, 2026. It describes implemented source paths and states native acceptance separately.

## The core loop

| Step | What happens | Go deeper |
| --- | --- | --- |
| Create or import | **New Design** scaffolds a project. Opening a `.fig` attempts to create an editable native project beside the import; the original `.fig` is not the working copy. The importer warns about known flattened or omitted structures; supported Boolean operations keep editable operands. | [First project](/docs/v2/getting-started/first-project), [Figma import](/docs/v2/formats/figma-import) |
| Design | Canvas tools, the inspector, Variables, and Motion mode change the live document. Pages and layers organize it. | [Editor](/docs/v2/editor), [Inspector](/docs/v2/editor/inspector) |
| Save as source | Autosave writes page and component `.fnx`, document metadata, variables, motion, and assets to the project folder. **Save As** can create another native project copy. | [Project layout](/docs/v2/concepts/document-model), [.fnx](/docs/v2/formats/fnx) |
| Edit source | Code lets you edit the active page or component `.fnx` and paired JSON, plus `doc/variables.json`; it lists `fanta.json` and `workspace.fnx` read-only. It validates changes before saving and reloading the canvas. External editors can change other supported project files; Fanta validates those on reload. Embedded Find searches the active FNX or JSON buffer; **Discard draft** affects the selected buffer. Source Save and a canvas-driven source refresh preserve text Undo. A dirty Code buffer temporarily locks canvas edits while accepted properties of one selected layer remain readable. | [Design as source](/docs/v2/concepts/fnx-design-as-source) |
| Review | In non-Store builds, Fanta initializes Git for a new project when available and when it is not already inside a repository. **Review Changes** and **Commit…** expose file changes when a repository is present. Store feature builds skip automatic Git setup. | [Version control](/docs/v2/guides/version-control-designs) |
| Share output | Export the active page or selected layers from the inspector as PNG, JPEG, SVG, or PDF. Dev mode supports inspection and page-bound handoff marks. | [Export](/docs/v2/formats/export), [Dev mode](/docs/v2/editor/dev-mode) |

### What is in a project?

A native project has a `fanta.json` manifest, `pages/<slug>/page.fnx`, reusable component source in `components/<slug>/master.fnx` (or `components/<set>/<variant>/master.fnx` for a variant set in layout v5), document state under `doc/`, and an `assets/` tree. `doc/asset_library.json` records named media even before placement; `doc/motion.json` holds authored motion data. New projects seed `AGENTS.md`, a project-local `fanta.md` design specification, and FNX helper files without replacing a customized specification. `exports/` and previews are output paths, not the source of truth. [Project structure and source rules →](/docs/v2/concepts/document-model)

Structural canvas saves retain authored FNX attributes on surviving nodes and source comments when supported. A deletion or type change that would silently lose source-only data can make Save refuse the change with a preservation error. Saved files remain intact, but the live canvas edit may remain until Undo; edit FNX directly to remove that data intentionally. [Source preservation →](/docs/v2/concepts/fnx-design-as-source)

On direct-download macOS, a fresh `.fig` import stages a complete sibling project before publishing it; if that first publication fails, the parsed design stays open for a save retry. Existing project saves use the transaction journal, and unchanged generated design files are not rewritten. A received project with `.fanta` settings or executable Git configuration can open in **Restricted Mode** until you review and trust it. [Import →](/docs/v2/formats/figma-import) · [Project format →](/docs/v2/formats/fant)

## Edit by hand

### Canvas and organization

- Select, marquee, pan, zoom, resize, rotate, nudge, duplicate, group, frame, and ungroup layers. Snapping uses the grid and edges or centers in the active page or opened component subtree; a different page does not attract the drag. A Select gesture cancels its pending move if its mouse press is lost. Scale selected content proportionally; the inspector also exposes rotate, flip, align, distribute, and Tidy up for eligible selections. Duplicating a component or complete variant set carries its definitions and internal links. Same-document Paste reuses live definitions, or restores captured definitions with new IDs if the originals were removed. Cut, Delete, and Duplicate respect layer locks; Paste validates component dependencies before applying a change. [Canvas tools →](/docs/v2/editor/tools)
- Create and manage pages. The layers panel supports selection, renaming, nesting, order changes, visibility, and locking. [Pages and layers →](/docs/v2/concepts/pages-world-space)
- Draw frames and sections, shapes, arrows, text, vector paths, and freehand marks. Edit path geometry, and convert a suitable single vector path into **Text on Path**. Path editing also joins, closes, simplifies, and reverses paths, bends segments, breaks a path at an anchor, and deletes curved anchors. Double-click can edit selected text or vectors, crop an image, drill into a container, or reveal properties, depending on the node. Rounded ancestor clips exclude invisible child artwork from authoring hits. Editable Design Crop shows Ratio, Cancel, and Apply controls; Apply commits a pending crop as one undoable change. Its controls have narrow-canvas insets. Right-click exposes applicable edit, structure, and component actions. [Canvas tools →](/docs/v2/editor/tools), [Vectors and text paths →](/docs/v2/concepts/vectors-icons-svg)
- Paste bitmap images, or use the local picker to place supported raster images and MP4 video. Editable SVG can come from Project Assets or a supported generation result; audio is placed from Project Assets. Canvas copy and paste of design layers can cross pages within one document; a cross-document canvas paste is explicitly rejected. [Media and import →](/docs/v2/formats)
- Open **Assets** in the file inspector to reuse stored images, SVG, MP4, or audio across pages. Generated results can be added to the project before placement. [Project Assets →](/docs/v2/editor/assets)

### Inspect and style

The inspector includes position, size, rotation, corner properties, opacity, blend, fills, strokes, typography, effects, layout, component controls, interactions, and export settings. The exact controls depend on what is selected. The image and video paint source chooser lists compatible project media and refreshes after asset, layer, Undo/Redo, or project reload changes. **Select matching layers** finds same-kind descendants on the active page; Sections match Sections rather than ordinary Frames or Groups. An editable TextPath layer offers **Edit object** for inline text editing. Bound paints and supported node properties display values resolved through the active variable mode. **Detach** bakes a bound fill’s current color for direct editing. Independent corner values remain separate, and mixed selections show mixed values; some mixed-value edits commit when the gesture ends rather than previewing live. During a dirty source draft, one selected layer’s accepted properties remain readable while writes stay locked. Constraint data persists, but constraint controls are disabled in the default Design inspector. The source supports 26 layer blend modes plus **Pass through** on groups; SVG export draws every blend mode as Normal, and PDF export draws several newer modes as Normal. Inspect a raster export when blend fidelity matters. [Inspector →](/docs/v2/editor/inspector) · [Export →](/docs/v2/formats/export)

Fanta commits a valid focused numeric property draft before Save, Save All, or closing with Save, and rejects an invalid draft without discarding it. Merely focusing a rounded X/Y display preserves its underlying fractional value; typed fractional TextPath X/Y edits follow painted bounds under transformed parents. These paths have bounded tests.

Frames support horizontal, vertical, and grid auto-layout, child sizing, alignment, wrapping, and size constraints. Grid tracks can use fixed, fractional, or content-sized values, and children can be pinned to cells; Figma grid behavior still has gaps, including auto rows and spanning-child sizing. Components and instances support reusable masters, variant sets, properties, and instance values. A project variant set can appear as one frame on the first visible page and has one source folder containing its variants. Instance actions resolve the visible member from the set default, overrides, and active variable modes. Detach preserves supported appearance and refuses combinations it cannot preserve. Variable collections support modes, aliases, typed values, and property bindings. Variables can also hold enum options and project-image values, including image-fill bindings. Agents can edit these structures through the live operation surface, including fill and effect stacks, per-side and dashed strokes, constraints, and shapes. Effects beyond drop/inner shadows and layer/background blur remain unsupported. [Auto-layout →](/docs/v2/concepts/auto-layout) · [Components →](/docs/v2/concepts/components) · [Variables →](/docs/v2/concepts/variables)

Instance text exposed through a component property can use the placed instance’s active variable mode. A direct text-content variable binding stays authoritative and is read-only in instance text editing; change the variable or binding instead. **Go to main component** uses the currently resolved variant member and pauses scope navigation while source edits are pending. [Components and instances →](/docs/v2/concepts/components)

### Templates and inline variables

Text and TextPath content can include `{{name}}` tokens. A token displays a string, number, boolean, or enum variable in the text layer's active mode. Use `{{Collection/Name}}` when a bare name is ambiguous; an unresolved token stays visible as typed. The saved source and the text editor retain the token rather than replacing it with its displayed value. [Variables →](/docs/v2/concepts/variables)

A template layer can store rules that forbid specific edits, such as moving, resizing, deleting, duplicating, or changing its text. The canvas lock control enters **Fill mode**. In that mode, canvas gestures, Delete, Duplicate, text editing, and Design inspector edits honor the stored rules. Rules can be authored in FNX or through the Rust design API. The inspector cannot show or edit the rules, and placeholders have no overlay yet. Multi-selection arrangement or transforms, variable bindings, and grouping do not consistently enforce the rules, so Fill mode is a partial guard. The signed 1.0 installer does not include this 2.0 source workflow. [FNX →](/docs/v2/formats/fnx) · [Editor surfaces →](/docs/v2/editor/surfaces)

### Prototype, animate, and discuss

Fanta has prototype interactions and preview surfaces. Closing an interaction detail keeps its interaction; **Remove** deletes it. Prototype actions include conditional branches, numeric variable adjustments, boolean toggles, and enum cycling. The presentation engine supports Contain, Cover, and Fill modes and preserves the backdrop behind overlays; the editor has no verified control for choosing a fit mode. Motion mode supports clips, tracks, keyframes, playback, typed Current time seeking, and guarded auto-keyframe editing; time comments can anchor feedback to a point in an animation. Clips store frame rate, loop mode, scope, and transform origins, and a clip exports as Motion JSON, Figma Motion JSON, a Claude Motion Stage package, an MP4 video, a GIF, or PNG frames. [Prototyping →](/docs/v2/concepts/prototyping) · [Motion →](/docs/v2/editor/motion)

Canvas comments support pins, replies, mentions, attachments, and resolution. AI Review findings anchor to layers and carry a severity, category, and review run ID. A suggested content-editing fix can be applied explicitly from its thread as one undo step; a review does not apply it automatically. Comments and page-bound measurements or developer annotations are saved with project metadata. They are project-local, not live multiplayer comments. [Comments →](/docs/v2/editor/comments) · [Review →](/docs/v2/agents/review-revision) · [Dev mode →](/docs/v2/editor/dev-mode)

### Dev inspection

Dev mode switches to a read-only inspection session for art and Code source. It offers layer inspection, measurements, annotations, and Saved Code for handoff. Measurements and annotations remain editable page marks. The **Readiness** control is currently unavailable. [Dev mode →](/docs/v2/editor/dev-mode)

## Work with agents

**External agents.** Fanta's local MCP server is enabled by default and can be turned off in Settings. With a design open and the server running, the `fanta --mcp-stdio` bridge connects clients such as Claude Code and Codex to the focused design. The server registers **14 tools**:

| Tool | Purpose |
| --- | --- |
| `get_editor_state` | Focused page or component, selection, bounds, and placement hints. Its component preview is capped at 100; `component_count` and `more_components` signal when to page the design system. |
| `get_guidelines` | Design guidance and the project's `fanta.md` context. |
| `get_design_system` | Component properties, variants, variable collections, modes, values, and bindings. One `offset`/`limit` independently pages components, sets, and variables (default 100, maximum 200); follow each `more_*` flag. |
| `prepare_design_asset` | Open an image or SVG generation draft for user review; it does not submit generation. |
| `batch_get` | Read nodes and geometry; page large results with `offset` and `limit`. A page listing may traverse at most 1,000 nodes and each response is capped at 256 KiB. Choose `summary`, projected `style`, or `raw` detail (raw requires exact IDs). |
| `batch_design` | Stream 44 typed creation, layout, styling, variable, and component operations, including enum option changes. Content edits form one undoable batch; selection- or viewport-only batches create no content undo step. Optional activity identifies the editing agent. |
| `get_screenshot` | Inspect a rendered page or node, optionally at a Motion clip playhead. |
| `read_fnx_source` | Read a bounded slice of a project's source. |
| `validate_fnx_source` | Validate a complete FNX or supported project JSON candidate without writing it. |
| `import_image` | Store an image from a path, HTTP(S) URL, or encoded source in Project Assets. |
| `list_comments` | Read comment threads on a page. |
| `reply_comment` | Reply to a thread and optionally resolve it. |
| `add_comment` | Place an agent comment at a page position or anchor it to a layer; review metadata and a suggested content-editing fix are optional. |
| `report_agent_activity` | Show a named agent's current page, node, source file, or workspace focus in the local app. |

The connection command copied by the running app includes its executable and instance data directory. Activity reports can follow an agent across the Canvas, Variables, and Code workspaces; idle reports expire. They are not cross-agent locks or networked collaboration. [Connection guide →](/docs/v2/getting-started/connect-an-agent) · [Tool reference →](/docs/v2/tools)

**In-app agent.** The docked Agent Panel can inspect and edit the canvas through native design tools. It has review and planning modes, design comments, project image import, and activity reporting paths. **AI Review** covers the active page and starts from the Agent Panel's new-thread menu, the Design menu, or the canvas toolbar. **Ultrareview** covers every page and starts from the new-thread or Design menu; both prepare a Review-profile draft for you to send. **Plan & Build** opens an empty Plan-profile thread for the open design from the new-thread or Design menu or <code>/plan-build</code>; **Apply plan** then switches the thread to Write to implement the whole plan. Canvas edit batches each form an undo step. **Add to Agent** in the canvas and layers context menus attaches selected layers as a snapshot mention to an unsent prompt; selecting that mention returns to the layers. The model button lists favorites or the current provider's models, with **More Models**, **Search Models…**, and an **Effort** submenu when supported. A native Agent turn stops after 64 model requests, including continuations and agent-managed retries, while completed work remains; this is not a credit limit. Native specialist agents can share the lead chat's reference images with supported models. The managed provider reads chat models and credit estimates from a signed-in catalog; other providers can be configured. Its `evaluate_with_jev` tool requests typed decisions from the hosted service when signed in. The generation workspace can hand a draft design request to the panel for review before sending. [Agents and AI →](/docs/v2/agents)

**Programmatic design in source.** The Rust `fanta-api` crate offers an in-process `DesignSession` for an in-memory design, a saved project, or a `.fant` snapshot. It exposes node editing, typed property discovery, explicit undo steps, polled node-change events, text variables, image placeholders, roles, and 25 editing scopes. It can fill a template from a data row and export a separate result for each row. The separate `fanta-engine` worker has source-level `inspect`, `create_page`, `apply`, `add_comments`, `project`, `render`, `fill_template`, `export_batch`, and `changeset` steps. These are developer and cloud-engine source interfaces, not extra tools in the 14-tool local MCP server or a deployed public API. Node or JavaScript bindings and a hosted engine are not shipped. [Architecture →](/docs/v2/reference/architecture) · [Roadmap →](/docs/v2/roadmap)

**Generation workspace.** Signed-in users can search the live catalog for image, video, audio, and vector workflows. Recipes and controls depend on the selected model, including video frames, duration, resolution, and audio options where supported. Results can be previewed, saved, reused as source, or added to Project Assets. Saved uncertain submissions can be retried or recovered before starting another job. Placed images become bitmap layers; supported SVG becomes editable vectors; MP4 becomes video; WAV, MP3, and FLAC become audio layers. Public accounts need sign-in and purchased credits for managed generation. [Media generation →](/docs/v2/agents/media-generation)

**Settings and account.** Settings manages appearance, canvas panels, source editing, model providers, hosted tools, MCP connections, account, billing, and privacy controls. Settings, About, and the app menu show update status and controls; no signed update feed or replacement installation has been verified yet. Billing usage charts use rolling 7, 30, or 90-day UTC windows when the service provides data; boundary calendar days can be partial. New purchases use web Billing. Public accounts have no free AI trial or signup credits; hosted AI requires purchased credits. Existing founder exceptions are restricted on the backend. The hosted MCP connections used by Fanta's in-app agent are separate from the 14-tool local canvas server above. A Mac App Store feature build blocks Fanta from launching local agent, MCP, and terminal processes; remote HTTP MCP connections remain available. [Settings and build differences →](/docs/v2/editor/settings)

## Formats and output

| Format or output | Current behavior |
| --- | --- |
| Native project folder | Editable, source-backed, and suitable for Git; Save As creates another copy. Layout v5 groups a variant set and its members under one component folder; older v4 projects upgrade on save. [Details →](/docs/v2/formats) |
| `.fnx` | JSX-like page/component source. Its printer retains finite numeric values, including very small ones, instead of rounding them to zero. Complete candidates can be validated before writing. [Syntax and limits →](/docs/v2/formats/fnx) |
| `.fig` | Opens through an importer and attempts a native sibling project. Supported Boolean operands remain editable; known structure losses receive warnings. Import fidelity and write access vary. [Details →](/docs/v2/formats/figma-import) |
| Images and local MP4 | Supported raster images can be pasted or placed through the local picker; it also places MP4 video, which can be trimmed without changing the source file. [Details →](/docs/v2/editor/assets) |
| `.fant` | A snapshot/container format supported by the format layer; the live editable project is the folder. [Details →](/docs/v2/formats/fant) |
| PNG, JPEG, SVG, PDF | Inspector export for a selection or page, with scale, dimensions, and presets where supported. JPEG uses fixed quality 95 and loses transparency; choose PNG when exact pixels or alpha matter. [Details →](/docs/v2/formats/export) |
| Motion exports | The Design menu exports the selected animation as Motion JSON, Figma Motion JSON, a Claude Motion Stage package, MP4 video, GIF, or PNG frames. The Figma variant reports unsupported tracks; destination node mapping and resting placement are required before a Figma plugin can apply supported manual tracks. MP4 needs `ffmpeg`. [Motion export →](/docs/v2/formats/export#motion-exports) |
| Static website | The v2 `fanta-site` command compiles a saved project and packages a read-only site with one URL per design page. It needs a separately built, matching runtime from Fanta-JS. The generated viewer navigates pages and pans or zooms; it does not play prototype interactions or motion. [Website export →](/docs/v2/formats/website-export) |
| Runtime bundle | The native `fanta-compile` command produces a `program.fanta` bundle for a matching runtime. The source auth-wizard example uses a custom runtime page for prototype interactions, unlike the read-only generated site. This is a source workflow without packaged 2.0 or public browser acceptance. [Runtime bundle →](/docs/v2/formats/runtime-bundle) |

## Current limits

- Fanta 2.0 targets **Apple Silicon macOS** first. Windows has a source build, CI checks, and an installer packaging workflow; the installer is unsigned by default and has no accepted public release. Its canvas uses CPU rendering, with no video playback or audio preview. A Linux installer remains under review. [Windows setup and install notes →](/docs/v2/getting-started/install)
- Fanta 2.0.0 has no installer yet. Its review, variable, prototype, motion, vector, website, and updater paths have source and test coverage, but no installed-app acceptance.
- Some visible tools and inspector actions remain incomplete. Fanta reports unavailable actions where possible. Grid auto-layout is implemented with the Figma behavior gaps above; effects are limited to drop/inner shadows and layer/background blur, and Dev **Readiness** is unavailable. Template Fill mode does not enforce every edit path, and SVG/PDF exports have the blend-mode fallbacks described above. [Editor status →](/docs/v2/editor/tools)
- Large `.fig` imports can be slow and memory intensive. Source reads and node reads have response limits, including a 1,000-node page-listing traversal budget, so agents should page through large documents. [Troubleshooting →](/docs/v2/mcp/troubleshooting)
- In non-Store builds, Fanta prefers its bundled Git and falls back to a system `git` for automatic initialization outside existing repositories. A design still saves if `git init` fails. Automatic initialization is disabled in the Mac App Store feature build. [Version control →](/docs/v2/guides/version-control-designs)
- A generated result over 128 MiB cannot be added to Project Assets. Placing a bitmap is also limited to 32 MiB, 32 megapixels, and 16,384 px per side; the local MP4 picker has a 100 MiB cap. Audio needs a decodable duration and is placed through **Add to project → Assets → Place**, not the direct **Add to design** action. [Project Assets →](/docs/v2/editor/assets)
- Bounded MP3 placement, Save, Undo/Redo, and cold storage checks pass, but cold Audio preview was absent in the checked project. WAV preview and broader audio recovery remain unverified. [Media generation →](/docs/v2/agents/media-generation)
- Source synchronization has conflict handling and save recovery, but an external write to the same path can still race Fanta's check and rename. Fanta keeps the last valid canvas when an external source reload fails and reports the error for repair. Recent changes reduce redundant reloads and preserve unaffected layout geometry, yet large-project Save and some draft-recovery journeys remain under release validation. Keep Git history for important projects. [Source editing →](/docs/v2/concepts/fnx-design-as-source)
- Large-page rendering and native responsiveness remain under validation. On macOS, Fanta normally uses Skia Graphite on Metal and falls back to Ganesh if Graphite cannot start. Retained translation is enabled by default; `FANTA_RETAINED_TRANSLATION=0` disables it. Canvas images decode on background threads at the size they are drawn, so an image can show a light grey wash, or look soft, for a moment while it decodes. Bounded checks do not establish a general native drag latency target.
- No signed 2.0 package exists yet, so installation, updates and migration from 1.0 are unverified. [Build from source →](/docs/v2/getting-started/install)
- Node graph, generic AI artifact, and embed node types render as placeholders. Existing 3D content can survive unrelated edits and saves, but that does not establish a complete 3D editor.
- Canvas comments and agent cursor presence are local to the open app and project. Real-time multi-user editing and cross-agent locks are not part of the current implementation.
- The current external MCP surface is the 14 registered tools above. Older references to a `:3846` HTTP server, 127 design tools, `cargo run -p fanta-app`, or `save_document` describe a different implementation.
- App keymap actions use `fanta::` and app links use `fanta://`. Fanta 1.0 used `zed::` and `zed://`, so review custom keymaps and links when you move from 1.0. [Shortcuts →](/docs/v2/editor/shortcuts)

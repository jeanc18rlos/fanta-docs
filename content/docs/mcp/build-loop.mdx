Every good build session follows the same loop. Skipping the front of it — the
playbook and guidelines — is the single most common reason an agent produces
drifting, absolutely-positioned, un-screenshotted output. Start here, every time.

```text
agent_playbook → get_guidelines → inspect → build → verify → save_document
                                     ▲                  │
                                     └──── iterate ─────┘
```

<Steps>

<Step>

### `agent_playbook` — load the rules of the house

The first call of any session. `agent_playbook` returns the operating manual for
*this* editor:

- **~34 principles** — the hard rules (nesting, overrides, fill-to-width,
  verify-with-a-node, compact canvas, references-first).
- **A ~37-step recommended flow** — the exact order to inspect, assemble, and
  verify.
- **The official tool list, grouped** — `system`, `visible_agents`,
  `inspection`, `references`, `vision`, `persistence`.
- **`live: true`** — confirmation that you are driving the visible editor, not a
  headless doc.

```json title="tools/call"
{ "name": "agent_playbook", "arguments": {} }
```

Read the principles before you build. They are the condensed form of everything
on [Get the best output](/docs/mcp/best-output).

</Step>

<Step>

### `get_guidelines` — pull the right guide and style

`get_guidelines` returns curated, reference-grade guidance in two categories:

- **`guide`** — _how to build a kind of thing._ Built-in guides include **Design
  System**, **Web App**, **Mobile App**, **Table**, **Slides**, **Landing
  Page**, **Code**, **Tailwind**, **agentic-design-workflow**,
  **brand-color-system**, **design-system-composition**,
  **figma-like-editor-shell**, **pencil-parity-agent-workflow**, and
  **reference-driven-design**.
- **`style`** — _the visual language to build in._ Built-in styles include
  **Fanta Futurist**, **Figma Clean Dark Light**, and **Product Data Grid**.

```json title="Fetch a guide and a style"
{ "name": "get_guidelines", "arguments": { "category": "guide", "name": "Web App" } }
```

```json
{ "name": "get_guidelines", "arguments": { "category": "style", "name": "Figma Clean Dark Light" } }
```

Pick the guide that matches the artifact (a dashboard → **Web App** or **Table**;
a marketing page → **Landing Page**) and a style that matches the look. The guide
shapes structure; the style shapes color, type, and rhythm.

</Step>

<Step>

### Inspect — read before you write

Capture the current state so you build *into* the document instead of guessing.

```json title="Survey the editor"
{ "name": "get_editor_state", "arguments": {} }
```

```json title="Read the scene graph"
{ "name": "get_document", "arguments": {} }
```

```json title="Resolved layout of a subtree"
{ "name": "snapshot_layout", "arguments": { "node": "frame_hero" } }
```

```json title="Batch-read many nodes at once"
{ "name": "batch_get", "arguments": { "nodes": ["frame_card", "txt_title", "btn_cta"] } }
```

<Callout type="warn">
  Many reads are scoped to the **active page**. Capture node ids **at creation
  time** rather than re-querying across pages — the same lookup can return
  nothing once you switch the active page.
</Callout>

</Step>

<Step>

### Build — assemble bottom-up with auto-layout

Create leaves, reparent them into frames, then turn frames into auto-layout
stacks. `batch_design` runs a sequence of tool calls in one round-trip — the
fastest way to assemble a section.

```json title="batch_design: build a card row, then lay it out"
{
  "name": "batch_design",
  "arguments": {
    "ops": [
      { "tool": "create_frame", "args": { "name": "Card", "w": 320, "h": 180 } },
      { "tool": "create_text",  "args": { "name": "Title", "text": "Revenue" } },
      { "tool": "create_text",  "args": { "name": "Value", "text": "$48,210" } },
      { "tool": "reorder", "args": { "node": "Title", "into": "Card", "to": "front" } },
      { "tool": "reorder", "args": { "node": "Value", "into": "Card", "to": "front" } },
      { "tool": "set_auto_layout", "args": {
          "node": "Card", "direction": "vertical", "gap": 8,
          "padding": 16, "primary_sizing": "hug", "counter_sizing": "fixed"
      } }
    ]
  }
}
```

The order matters: nodes drop on the active page, you **reparent each with
`reorder {into, to:"front"}`** (front appends as the last child = flow order),
then `set_auto_layout` the container. Assemble leaves into rows, rows into cards,
cards into sections, sections into the page. Other build verbs:
`set_layout_child` (per-child stretch/grow), `insert_instance` and
`set_instance_override` (components). See
[Get the best output](/docs/mcp/best-output) for the exact rules.

</Step>

<Step>

### Verify — screenshot a frame, then critique

Never trust the build blind. Render a **single frame** (chrome-free, no OS
permissions) and look.

```json title="export_png a frame — always pass a node"
{ "name": "export_png", "arguments": { "node": "Card" } }
```

```json title="Or a fast screenshot of the same frame"
{ "name": "get_screenshot", "arguments": { "node": "Card" } }
```

```json title="Compare against a saved reference"
{ "name": "compare_screenshot", "arguments": { "node": "Card", "reference": "ref_card_v2" } }
```

```json title="Critique before saving"
{ "name": "review_design", "arguments": { "node": "Card" } }
```

<Callout type="error">
  Always pass a frame `node`, and keep frames **≤ 1920×1080**. With no `node`,
  `export_png` / `get_screenshot` default to the whole document — every page
  across world space — and **time out** (`visible editor timed out`). Never
  screenshot a page or the canvas.
</Callout>

Run `review_design` on each major section, fix what it flags, and loop back to
**Build**. Iterate broad → refine.

</Step>

<Step>

### `save_document` — persist before you walk away

In-memory state is **not** auto-persisted. A relaunch reloads from disk, so save
once the section is right.

```json title="tools/call"
{ "name": "save_document", "arguments": {} }
```

<Callout type="warn">
  If you intend to relaunch the live app, `save_document` **first** — otherwise
  the work you just did vanishes on reload.
</Callout>

</Step>

</Steps>

## The loop in one line

`agent_playbook` (rules) → `get_guidelines` (guide + style) → inspect
(`get_editor_state`, `get_document`, `snapshot_layout`, `batch_get`) → build
(`create_*`, `batch_design`, `reorder`, `set_auto_layout`, `set_layout_child`,
`insert_instance`, `set_instance_override`) → verify (`export_png` /
`get_screenshot` / `compare_screenshot` / `review_design`, always with a `node`)
→ `save_document`.

The Fantaisa desktop app **is** an MCP server. There is no plugin to install, no
export step, and no headless render farm in the middle: when you run the editor,
it opens a Model Context Protocol endpoint and any MCP-capable agent — Claude
Code, OpenAI Codex, GLM, or the in-app brain — connects to the **running editor**
and mutates the **real document you are looking at**, live.

This is the core of Fantaisa. Other tools bolt an assistant onto a design app.
Fantaisa exposes the entire editor as a tool surface, so an agent designs the way
you do: it creates frames, nests them with auto-layout, binds variables, swaps
component instances, screenshots its own work, critiques it, and saves — all on
the canvas in front of you.

<Callout type="info">
  Every agent edit is an ordinary `Operation` in the document model — the same
  undoable, replayable mutation a human click produces. Undo/redo, history, and
  collaboration treat agent edits and human edits identically.
</Callout>

## The model

```text
  Agent (Claude Code / Codex / GLM)
        │  JSON-RPC 2.0  (MCP 2024-11-05)
        ▼
  Fantaisa MCP endpoint  ──►  DocTool intent  ──►  Operation  ──►  live document
        ▲                                                              │
        └──────────────  export_png / get_screenshot  ◄───────────────┘
```

Three properties make this work:

- **One tool surface, everywhere.** The ~127 tools the in-app AI uses are the
  same tools external agents call. There is no second-class API — anything you
  can do by hand, an agent can do over MCP, and vice versa.
- **Mutations go through `DocTool`.** Tools express *intent* (`create_frame`,
  `set_auto_layout`, `set_instance_override`), which lowers to an `Operation`.
  Agents never poke app internals; they cannot break document invariants.
- **Agents read a compact view.** Inspection tools return a small
  `CanvasContext` — node ids, layout, variables — not arbitrary source state, so
  the agent reasons about the design, not the renderer.

## Transports

Pick the transport that matches your client and your goal.

| Transport | Endpoint / command | Targets | Use it when |
| --- | --- | --- | --- |
| **Streamable HTTP** | `POST http://127.0.0.1:3846/mcp` | The **visible** running editor | Codex and any HTTP-capable client. The default. Override the address with `FANTA_MCP_ADDR`. Newline-delimited JSON-RPC 2.0 is also accepted on the port. |
| **Headless `fanta-mcp`** | `cargo run -p fanta-ai --bin fanta-mcp` | An **in-memory** doc (no UI) | CI, automation, and batch jobs. Owns its own document; can load a `.fant` or `.fig` and never opens a window. |
| **`fanta-mcp --live` (proxy)** | `cargo run -p fanta-ai --bin fanta-mcp -- --live` | The **visible** running editor | Stdio-only clients (Claude Code). A thin stdio→HTTP proxy that forwards to the desktop editor at `:3846`. |

<Callout type="info">
  HTTP and the `--live` proxy drive the **same** visible document — the proxy
  just lets stdio-only clients reach it. Headless `fanta-mcp` is the odd one out:
  it owns a private in-memory doc and shows nothing on screen.
</Callout>

The protocol is **JSON-RPC 2.0**, MCP version **2024-11-05**, in every mode.

## Talking to the endpoint

List the tools, then call one. This is the raw wire format every transport
speaks — most agents handle it for you.

```bash title="List the available tools"
curl -s http://127.0.0.1:3846/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

```json title="Call a tool"
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "create_frame",
    "arguments": { "name": "Card", "x": 0, "y": 0, "w": 320, "h": 180 }
  }
}
```

<Callout type="warn">
  Always start a real build session with `agent_playbook`, not `tools/list`.
  The playbook returns the principles, the recommended flow, and the curated
  tool groups so the agent builds with the grain of the editor. See
  [The build loop](/docs/mcp/build-loop).
</Callout>

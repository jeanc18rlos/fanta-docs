---
title: Troubleshooting
description: Diagnose connection, large results, and source reload issues.
---

## The client cannot connect

Open Fanta and focus a design before starting the stdio bridge. Use **Help → Connect Claude Code / Codex…** to copy the command for this running executable, including its `--user-data-dir` value. Check `fanta_live_mcp.enabled`, restart the client, and call `get_editor_state`. The bridge exits when the app is closed or MCP is disabled.

The documented bridge is for non-Store builds. If you are configuring an MCP server **inside** Fanta, check **Settings → MCP & Tools** for its status, scope, and connection type. A Mac App Store feature build cannot launch a local command-backed server; use a remote HTTP server there. External-client bridging to a packaged Store build has not been verified.

## The wrong design is active

`get_editor_state` reports the active page and selection. Focus the intended design and read state again. The server acts on the most recently focused canvas.

## A tree query is refused

`batch_get` caps responses at 256 KiB. Use smaller `limit`, `offset`, lower `depth`, or fewer exact IDs. A wide imported `.fig` page can have thousands of siblings.

## Source looks incomplete

`read_fnx_source` returns at most 64 KiB by default. Its `offset` is a **1-based line number**. Follow `truncated` and `next_offset`; use a larger `max_bytes` for an unusually long line (ceiling 1 MiB). Never replace a file based on a partial slice.

## Source did not reload

Validate a complete candidate with `validate_fnx_source`, save the `.fnx` file in the open project, and allow the reload. Leave generated `*.ids.json` files alone. Fanta logs live at `~/Library/Logs/Fanta/`.

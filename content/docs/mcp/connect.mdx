Every connection method talks to the same JSON-RPC 2.0 surface (MCP version
`2024-11-05`). The only choice is *which document* the agent drives — the visible
editor or a private headless doc — and *how* it reaches the endpoint.

<Callout type="info">
  Run every command below from the repository root
  (`/path/to/fanta`). The first build is slow; subsequent runs are fast.
</Callout>

## Start the editor first

For any **live** connection (Claude Code via the proxy, or an HTTP client), the
desktop app must be running. Launching it auto-starts the live MCP server on
`:3846` — no extra flag needed.

```bash title="Launch the editor (auto-starts live MCP on :3846)"
cargo run -p fanta-app
```

You only skip this for **headless** automation, which spawns its own document.

## Pick your client

<Tabs items={['Claude Code', 'Codex / HTTP', 'Headless']}>

<Tab value="Claude Code">

Claude Code speaks stdio, so it reaches the **visible** editor through the
`fanta-mcp --live` proxy — a thin stdio→HTTP bridge to `:3846`.

<Steps>

<Step>

### Start the editor

```bash
cargo run -p fanta-app
```

</Step>

<Step>

### Register the proxy with Claude Code

```bash
claude mcp add fantaisa -- cargo run -p fanta-ai --bin fanta-mcp -- --live
```

This stores a server named `fantaisa` that Claude Code launches on demand. The
proxy connects to the running editor and forwards every call.

</Step>

<Step>

### Or configure it by hand

Drop a `.mcp.json` in your project (or merge into your existing one):

```json title=".mcp.json"
{
  "mcpServers": {
    "fantaisa": {
      "command": "cargo",
      "args": ["run", "-p", "fanta-ai", "--bin", "fanta-mcp", "--", "--live"]
    }
  }
}
```

</Step>

<Step>

### Verify

In Claude Code, run `/mcp` to confirm `fantaisa` is connected, then prompt the
agent to call `agent_playbook`. If the editor window is open, you are designing
live.

</Step>

</Steps>

</Tab>

<Tab value="Codex / HTTP">

Codex and other HTTP-capable clients connect **directly** to the editor over
Streamable HTTP — no proxy. This is the default and lowest-latency path.

<Steps>

<Step>

### Start the editor

```bash
cargo run -p fanta-app
```

</Step>

<Step>

### Point the client at the endpoint

```text
POST http://127.0.0.1:3846/mcp
```

A typical HTTP-MCP client config:

```json title="MCP HTTP client config"
{
  "mcpServers": {
    "fantaisa": {
      "type": "http",
      "url": "http://127.0.0.1:3846/mcp"
    }
  }
}
```

</Step>

<Step>

### Verify

```bash
curl -s http://127.0.0.1:3846/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

A JSON array of tool definitions confirms the server is live. Newline-delimited
JSON-RPC 2.0 is also accepted on the same port for clients that prefer it.

</Step>

</Steps>

<Callout type="warn">
  Do **not** spawn `fanta-mcp` for Codex, and do **not** open a second editor
  instance. Codex connects over HTTP to the one running app. Two editors means
  two documents.
</Callout>

</Tab>

<Tab value="Headless">

Headless `fanta-mcp` is for CI and automation with **no UI**. It owns a private
in-memory document and can load a `.fant` or `.fig` to operate on.

<Steps>

<Step>

### Launch over stdio

```bash
cargo run -p fanta-ai --bin fanta-mcp
```

The process reads JSON-RPC 2.0 on stdin and writes responses on stdout. **stdout
stays pure JSON-RPC** — all logs go to stderr, so it is safe to pipe.

</Step>

<Step>

### Drive it from your runner

Point any stdio-MCP client at the binary, or feed it requests directly:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' \
  | cargo run -q -p fanta-ai --bin fanta-mcp
```

</Step>

</Steps>

<Callout type="info">
  Headless edits never touch the visible editor — it has its own doc. Use it when
  you want deterministic, windowless runs. Use the proxy or HTTP when you want
  the agent to design *on screen*.
</Callout>

</Tab>

</Tabs>

## Choosing the address

The HTTP endpoint binds to `127.0.0.1:3846` by default. Override it — for a
different port, or to run more than one editor — with `FANTA_MCP_ADDR`:

```bash title="Run the editor on a custom address"
FANTA_MCP_ADDR=127.0.0.1:4000 cargo run -p fanta-app
```

Point your HTTP client (or the `--live` proxy, which reads the same variable) at
the matching address.

## Run-command cheat sheet

| Goal | Command |
| --- | --- |
| Visible editor + live MCP on `:3846` | `cargo run -p fanta-app` |
| Headless in-memory server (stdio) | `cargo run -p fanta-ai --bin fanta-mcp` |
| Stdio→HTTP proxy to the visible editor | `cargo run -p fanta-ai --bin fanta-mcp -- --live` |

`.fnx` is Fantaisa's **design-as-source** format: React/JSX-style source files,
one per component and one per page, produced and parsed by the `fanta-fnx` codec.
Instead of an opaque per-node JSON blob, a design becomes readable source that
diffs and merges like code.

## Why design-as-source

A traditional design file is a tree of node JSON. A two-pixel nudge produces a
diff no human can read, and a merge conflict is unresolvable by hand. `.fnx`
flips that: the document is text that mirrors how the design is *structured*, so:

- **Diffs are code-like.** A renamed layer, a changed padding, a new variant read
  as a one-line change in `git diff`.
- **Git is the version history.** Branch, review, and merge designs with the same
  tools you use for code.
- **Designs and code converge.** A JSX-shaped tree of frames, text, and instances
  is legible to both designers and engineers.

## What a .fnx file looks like

Each file describes a subtree as nested, named elements with props — frames,
text, instances, and their layout and style — in the spirit of a component file:

```jsx title="Card.fnx"
<Frame name="Card" autoLayout="vertical" gap={8} padding={16} fill="#101418">
  <Text name="Title" size={18} weight={600} color="#FFFFFF">Revenue</Text>
  <Text name="Value" size={28} weight={700} color="#FFFFFF">$48,210</Text>
</Frame>
```

The codec is the source of truth for the exact grammar; treat the snippet above as
the shape, not a spec.

## Get .fnx out of a live document with export_jsx

`export_jsx` returns the `.fnx` source for any subtree, so you can lift a built
frame straight into a source file:

```json title="export_jsx for a node"
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"export_jsx","arguments":{"node":"Card"}}}
```

This is the design-to-code bridge: build visually with the
[MCP build loop](/docs/mcp/build-loop), then `export_jsx` the result into your
repository.

## A git workflow for designs

1. **Build or import** a page in the editor.
2. **`export_jsx`** the page (or component) to a `.fnx` file in your repo.
3. **Commit** it. The diff is readable, so PR review of a design is real review.
4. **Edit** either visually (re-export) or in source (hand-edit the `.fnx`).
5. **Merge** with normal git tooling — conflicts land on lines, not in binary.

<Callout type="info">
  `.fnx` is for source-control and code-convergence. For a portable single-file
  hand-off use the [`.fant` container](/docs/formats/fant); for the live editor the
  working format is the [project directory](/docs/formats/fant).
</Callout>

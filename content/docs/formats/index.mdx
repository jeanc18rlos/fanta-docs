Fantaisa has a deliberate split between the format you *work in*, the format you
*ship*, and the format you *diff*. Understanding which is which prevents the most
common data-loss mistakes — editing a stale export, or relaunching before a save.

## The format story

- **Project directory — the working format.** A live document is a directory on
  disk, not a single file. The desktop app reads and writes it as you edit. It is
  the source of truth for the in-app editor and the live MCP.
- **`.fant` — the container.** A single-file import/export bundle (manifest +
  migration + round-trip), produced by the `fanta-format` crate. Use it to hand a
  document to another machine or archive a snapshot. Image embedding is opt-in.
- **`.fnx` — design as source.** React/JSX-style per-component and per-page
  *source* files (the `fanta-fnx` codec) that replace per-node JSON. Git-friendly,
  with code-like diffs. `export_jsx {node}` returns `.fnx` for any subtree.
- **`.fig` — Figma import.** The `fanta-fig-interop` crate reads Figma's Kiwi
  format: components, instance overrides, variables, auto-layout, vectors, and
  effects, validated against a fidelity oracle.
- **Export — PNG / SVG / PDF.** The `fanta-export` crate and the MCP export tools
  (`export_png`, `export_svg`, `export_jsx`, `get_screenshot`) render the document
  for the outside world.

<Callout type="warn">
  In-memory state is **not** auto-persisted. Save the document before relaunching
  the live app or the work you just did is gone on reload.
</Callout>

## Where each format lives

| Format | Crate | Role |
| --- | --- | --- |
| Project directory | `fanta-app` + `fanta-doc` | Working format the editor reads/writes |
| `.fant` | `fanta-format` | Single-file import/export container, migration, round-trip |
| `.fnx` | `fanta-fnx` | Design-as-source codec, `export_jsx` |
| `.fig` | `fanta-fig-interop` | Figma (Kiwi) import |
| PNG / SVG / PDF | `fanta-export` | Render output for the outside world |

See [Architecture](/docs/reference/architecture) for how these crates fit
together and [the build loop](/docs/mcp/build-loop) for where `save_document`
sits in a session.

The working Fanta document is a directory containing <code>fanta.json</code>. It holds the design as project files and assets, making page and component changes inspectable in Git.

## Project layout

| Path | Contains |
| --- | --- |
| <code>fanta.json</code> | Project identity and schema information |
| <code>pages/&lt;slug&gt;/page.json</code> | Page identity, name, and order |
| <code>pages/&lt;slug&gt;/page.fnx</code> | Page node tree |
| <code>components/&lt;slug&gt;/master.fnx</code> | Component master node tree |
| <code>doc/variables.json</code> and related files | Tokens, modes, metadata, motion, and prototype state |
| <code>assets/</code> | Source binary assets, with an integrity index |
| <code>exports/</code> | Derived files from visual export |

Readable slugs are paths, while IDs identify pages and nodes. Keep IDs stable when editing existing content. Commit the manifest, source, sidecars, and referenced assets together.

Fanta saves canvas changes back to project files. It also watches for external edits and branch changes. The project writer uses atomic file replacement and a transaction journal for multi-file updates. If source is invalid or a canvas and external edit conflict, inspect the diagnostic instead of assuming the editor discarded or accepted either version. The Code workspace can edit FNX when the canvas is clean; an external editor can change it too.

## The .fant format

A <code>.fant</code> file is a single-file design snapshot. The format handler can import and export the document together with its assets. Opening a snapshot materializes an editable Fanta project; the original snapshot is not the live, versioned working document.

<Callout type="info">
The format library supports writing <code>.fant</code> snapshots, but the editor controls verified in the current app expose PNG, JPG, SVG, and PDF visual exports. For routine design handoff, share the editable project directory or one of those visual exports according to the recipient's needs.
</Callout>

See [FNX source](/docs/formats/fnx) for editing project files and [visual export](/docs/formats/export) for deliverables.
